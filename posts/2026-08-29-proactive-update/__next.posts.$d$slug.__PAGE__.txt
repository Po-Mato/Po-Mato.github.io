<h3 id="section-프로그램-stream-lab-go" tabindex="-1">프로그램: stream-lab.go<a href="#section-%ED%94%84%EB%A1%9C%EA%B7%B8%EB%9E%A8-stream-lab-go" class="heading-anchor" aria-label="프로그램: stream-lab.go 항목 링크">#</a></h3>
<p>생산자는 입력을 닫고 Stage만 출력을 닫는다. done은 출력 종료 이후 닫히므로 테스트가 종료 완료를 기다릴 수 있다. 변환 함수는 짧고 종료하는 계산이어야 한다.</p>
<pre><code class="language-go">package main

import (
	"context"
	"fmt"
)

// Stage owns out and done. The producer owns and closes in.
// transform must finish on its own; context cannot interrupt arbitrary code.
func Stage(ctx context.Context, in &#x3C;-chan int, transform func(int) int) (&#x3C;-chan int, &#x3C;-chan struct{}) {
	out := make(chan int)
	done := make(chan struct{})
	go func() {
		defer close(done)
		defer close(out)
		for {
			select {
			case &#x3C;-ctx.Done():
				return
			case value, ok := &#x3C;-in:
				if !ok {
					return
				}
				result := transform(value)
				select {
				case &#x3C;-ctx.Done():
					return
				case out &#x3C;- result:
				}
			}
		}
	}()
	return out, done
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()
	in := make(chan int, 3)
	for _, value := range []int{1, 2, 3} {
		in &#x3C;- value
	}
	close(in)
	out, done := Stage(ctx, in, func(n int) int { return n * 2 })
	for value := range out {
		fmt.Println(value)
	}
	&#x3C;-done
	fmt.Println("완료: 입력 종료와 출력 종료 확인")
}

</code></pre>
<p>첫 명령의 출력은 다음과 같다. 테스트는 네 Test 함수가 PASS이고 종료 코드가 0이어야 한다. race 검사는 지원되는 플랫폼과 C 컴파일러가 필요하다. race 실행 실패를 일반 테스트 통과로 대체해서 해석하지 않는다.</p>

</code></pre>
<p>검사 실패 시 ‘처리 goroutine 종료 시간 초과’는 종료 신호를 받지 못했다는 뜻이며 처리량 측정값이 아니다. 출력의 select를 직접 송신으로 되돌린 변형에서는 소비자 없는 취소 검사가 실패한다. 입력 ok 검사를 제거한 변형에서는 빈 입력 검사가 실패한다. 블로그 회귀 검사에서 이 두 변형을 임시 폴더에서 실행해 테스트가 문제를 잡는지도 확인한다.</p>
<h3 id="section-취소의-범위와-정리" tabindex="-1">취소의 범위와 정리<a href="#section-%EC%B7%A8%EC%86%8C%EC%9D%98-%EB%B2%94%EC%9C%84%EC%99%80-%EC%A0%95%EB%A6%AC" class="heading-anchor" aria-label="취소의 범위와 정리 항목 링크">#</a></h3>
<p><a href="https://pkg.go.dev/context">context 문서</a>에 따라 cancel을 호출해 관련 자원을 해제한다. 다만 취소는 임의 코드의 강제 중단이 아니다. transform이 무한 계산이나 취소를 무시하는 외부 I/O에 들어가면 이 Stage도 끝나지 않는다. 실제 I/O는 취소를 지원하는 API와 별도 제한 시간이 필요하다.</p>
<p>취소와 송수신이 동시에 준비될 때 취소만 우선한다고 가정하지 않는다. 이 예제는 ‘취소 직후 추가 처리 0개’나 트랜잭션 롤백을 보장하지 않는다. 처리 단계가 소유한 채널의 종료와 대기 해소를 확인하는 실습이다. 실행 후 만든 두 파일과 실습 폴더를 지우면 된다. Go 도구의 빌드 캐시는 별도로 남을 수 있다.</p>
