1a:T1c16,<h1>에이전트가 작성한 코드를 검증하는 개발자의 역할</h1>
<p>생성된 코드도 명시한 요구사항을 만족하는지 확인해야 합니다. 이 글은 상태 코드가 정상이어도 본문이 계약을 어길 수 있다는 점을 작은 로컬 실습으로 보여줍니다.</p>
<h2 id="section-1-코드-작성에서-시스템-설계로의-전환" tabindex="-1">1. 코드 작성에서 시스템 설계로의 전환<a href="#section-1-%EC%BD%94%EB%93%9C-%EC%9E%91%EC%84%B1%EC%97%90%EC%84%9C-%EC%8B%9C%EC%8A%A4%ED%85%9C-%EC%84%A4%EA%B3%84%EB%A1%9C%EC%9D%98-%EC%A0%84%ED%99%98" class="heading-anchor" aria-label="1. 코드 작성에서 시스템 설계로의 전환 항목 링크">#</a></h2>
<p>검토자는 입력과 출력, 실패 조건을 먼저 정해야 합니다. 테스트 통과는 정한 범위의 증거이며 보안·가용성·전체 시스템의 정확성을 보장하지 않습니다.</p>
<h2 id="section-2-코드-예시-에이전트가-작성한-코드의-검증" tabindex="-1">2. 코드 예시: 에이전트가 작성한 코드의 검증<a href="#section-2-%EC%BD%94%EB%93%9C-%EC%98%88%EC%8B%9C-%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%EA%B0%80-%EC%9E%91%EC%84%B1%ED%95%9C-%EC%BD%94%EB%93%9C%EC%9D%98-%EA%B2%80%EC%A6%9D" class="heading-anchor" aria-label="2. 코드 예시: 에이전트가 작성한 코드의 검증 항목 링크">#</a></h2>
<p>기존 예제의 <code>module_agent</code>는 fixture 정의가 없었고 <code>/health</code>의 200 여부만 검사했습니다. 아래는 실제 서버 호출 대신 상태 코드와 응답 문자열을 전달하는 결정적 fixture 실습입니다. 네트워크 통합 테스트와 구분해서 사용하세요.</p>
<h3 id="section-로컬-실습-응답-본문-계약-검사" tabindex="-1">로컬 실습: 응답 본문 계약 검사<a href="#section-%EB%A1%9C%EC%BB%AC-%EC%8B%A4%EC%8A%B5-%EC%9D%91%EB%8B%B5-%EB%B3%B8%EB%AC%B8-%EA%B3%84%EC%95%BD-%EA%B2%80%EC%82%AC" class="heading-anchor" aria-label="로컬 실습: 응답 본문 계약 검사 항목 링크">#</a></h3>
<p>교육용 계약은 상태 코드 200, JSON 객체, 문자열 <code>status</code>와 <code>service</code>를 요구합니다. <code>status</code>는 <code>ok</code>, <code>service</code>는 공백을 제외하고 비어 있지 않아야 합니다. 추가 필드는 허용합니다. 모든 API에 적용되는 표준이 아니라 이 실습의 선택입니다.</p>
<p><a href="/examples/contract-lab.py">전체 코드와 테스트 다운로드</a></p>
<p>Python 3.10 이상과 표준 라이브러리만 사용합니다. 파일을 빈 폴더에 저장하고 다음 명령을 실행하세요. 외부 API·패키지 설치·인증정보는 필요하지 않습니다.</p>

<pre><code class="language-python">"""외부 요청 없이 교육용 health 응답 계약을 검사한다. Python 3.10+."""
import json
import unittest


def validate_health(status_code, body):
    if status_code != 200:
        raise ValueError("http_status")
    try:
        data = json.loads(body)
    except json.JSONDecodeError as error:
        raise ValueError("invalid_json") from error
    if not isinstance(data, dict):
        raise ValueError("object_required")
    if "status" not in data or "service" not in data:
        raise ValueError("missing_field")
    if not isinstance(data["status"], str) or not isinstance(data["service"], str):
        raise ValueError("field_type")
    if data["status"] != "ok":
        raise ValueError("status_value")
    if not data["service"].strip():
        raise ValueError("empty_service")
    return data


class ContractTests(unittest.TestCase):
    def test_valid(self):
        self.assertEqual(validate_health(200, '{"status":"ok","service":"demo"}')["service"], "demo")

    def test_extra_fields_allowed(self):
        self.assertEqual(validate_health(200, '{"status":"ok","service":"demo","version":1}')["version"], 1)

    def test_invalid_responses(self):
        cases = [
            (503, '{}', "http_status"),
            (200, '{', "invalid_json"),
            (200, '[]', "object_required"),
            (200, 'null', "object_required"),
            (200, '{"status":"ok"}', "missing_field"),
            (200, '{"status":true,"service":"demo"}', "field_type"),
            (200, '{"status":"ok","service":1}', "field_type"),
            (200, '{"status":"failed","service":"demo"}', "status_value"),
            (200, '{"status":"ok","service":"  "}', "empty_service"),
        ]
        for status, body, reason in cases:
            with self.subTest(status=status, body=body):
                with self.assertRaisesRegex(ValueError, "^" + reason + "$"):
                    validate_health(status, body)


if __name__ == "__main__":
    unittest.main(verbosity=2)
</code></pre>
