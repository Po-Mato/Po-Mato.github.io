1d:T8f6f,<h2 id="section-tl-dr" tabindex="-1">TL;DR<a href="#section-tl-dr" class="heading-anchor" aria-label="TL;DR 항목 링크">#</a></h2>
<ul>
<li><strong>A2A vs MCP는 경쟁이 아니라 보완</strong>: MCP는 Agent-도구 연결(수평), A2A는 Agent-간 협업(수직) — 두 계층이 함께 산업 표준이 되고 있다</li>
<li><strong>Google의 전략적 포지션</strong>: 'Chip to Inbox' 수직 통합으로 AWS/MS 뒤追赶에서 차별화. Vertex AI를 Gemini Enterprise Agent Platform으로 rebranding하며 에이전트 플랫폼 전면에 나서다</li>
<li><strong>A2A v1.2의 핵심 혁신</strong>: Signed Agent Cards + cryptographic domain verification. 서로를 모르는 Agent 간의 trust 문제를 프로토콜 레벨에서 해결</li>
<li><strong>Apigee = MCP Bridge</strong>: 기존 API 게이트웨이를 Agent 도구 디스커버리 레이어로 전환. 150개 조직이 프로덕션에서 A2A를 실전 운영</li>
<li><strong>자가 검토 결론</strong>: " Pieces not Platform" 전략은 2023~2025년 클라우드 공룡들의 공통 허점이었다. Google의 이번 발표는 이것을 직접적으로 짚은 공격적 포지셔닝이다</li>
</ul>

<h2 id="section-1-서론-왜-지금-google의-agent-전략인가" tabindex="-1">1. 서론: 왜 지금 Google의 Agent 전략인가<a href="#section-1-%EC%84%9C%EB%A1%A0-%EC%99%9C-%EC%A7%80%EA%B8%88-google%EC%9D%98-agent-%EC%A0%84%EB%9E%B5%EC%9D%B8%EA%B0%80" class="heading-anchor" aria-label="1. 서론: 왜 지금 Google의 Agent 전략인가 항목 링크">#</a></h2>
<p>2026년 4월, Google Cloud Next 키노트는 'The Agentic Cloud'라는 제목으로 열렸다. Thomas Kurian의 핵심 메시지는 명확했다:</p>
<blockquote>
<p><em>"다른 업체들은 여러분에게 조각들(pieces)을 건네고 있어요. 플랫폼이 아니라."</em></p>
</blockquote>
<p>이 발언이瞄准하는 대상은 명확하다. AWS의 Bedrock, Microsoft Azure의 Copilot Studios — 모두 훌륭한 개별 컴포넌트이지만, 이를 단일 플랫폼으로 통합하는 힘이 부족했다.</p>
<p>반면 Google의 theses는 다음과 같다:</p>
<pre><code>Chip(GPU/TPU) → Model(Gemini/Gemma) → Runtime(ADK) → Protocol(A2A/MCP) → Distribution(Gmail/Docs/Workspace) → Enterprise(Inbox)
</code></pre>
<p>이 수직 통합이 의미하는 바를 기술적 레벨에서 분석한다.</p>

<h2 id="section-3-핵심-아키텍처-분석-a2a-vs-mcp-双層-프로토콜" tabindex="-1">3. 핵심 아키텍처 분석: A2A vs MCP 双層 프로토콜<a href="#section-3-%ED%95%B5%EC%8B%AC-%EC%95%84%ED%82%A4%ED%85%8D%EC%B2%98-%EB%B6%84%EC%84%9D-a2a-vs-mcp-%E5%8F%8C%E5%B1%A4-%ED%94%84%EB%A1%9C%ED%86%A0%EC%BD%9C" class="heading-anchor" aria-label="3. 핵심 아키텍처 분석: A2A vs MCP 双層 프로토콜 항목 링크">#</a></h2>
<h3 id="section-3-1-두-프로토콜의-역할-구분" tabindex="-1">3-1 두 프로토콜의 역할 구분<a href="#section-3-1-%EB%91%90-%ED%94%84%EB%A1%9C%ED%86%A0%EC%BD%9C%EC%9D%98-%EC%97%AD%ED%95%A0-%EA%B5%AC%EB%B6%84" class="heading-anchor" aria-label="3-1 두 프로토콜의 역할 구분 항목 링크">#</a></h3>
<p>가장 흔한 오해는 "A2A와 MCP가 경쟁 관계"라는 것이다. 실제로는 <strong>완전히 다른 계층을 담당</strong>한다:</p>

<p><strong>MCP의 역할</strong>: Agent가 외부 도구, 데이터 소스, API에 접속하는 방식. "이 Agent는 무엇을 할 수 있는가?"</p>
<p><strong>A2A의 역할</strong>: 서로 다른 플랫폼 위에서 동작하는 Agent들이 직접 통신하는 방식. "이 Agent는 다른 Agent와 어떻게 협업하는가?"</p>
<h3 id="section-3-2-a2a-v1-2-signed-agent-cards와-cross-platform-trust" tabindex="-1">3-2 A2A v1.2: Signed Agent Cards와 Cross-Platform Trust<a href="#section-3-2-a2a-v1-2-signed-agent-cards%EC%99%80-cross-platform-trust" class="heading-anchor" aria-label="3-2 A2A v1.2: Signed Agent Cards와 Cross-Platform Trust 항목 링크">#</a></h3>
<p>A2A의 가장 큰 도전은 이것이다:</p>
<blockquote>
<p><strong>서로를 모르는 두 Agent가 어떻게 mutually trusted collaboration을 구축하는가?</strong></p>
</blockquote>
<p>예를 들어, Salesforce Agentforce Agent가 Google Vertex AI Agent에게 태스크를 위임할 때, 다음 조건이 충족되어야 한다:</p>
<ol>
<li><strong>Identity Verification</strong>: 이 요청이 정말 Salesforce Agentforce에서 온 것인가?</li>
<li><strong>Capability Discovery</strong>: Google Agent는 Salesforce Agent의 능력을 어떻게 아는가?</li>
<li><strong>Security Policy Enforcement</strong>: 조직 간 보안 정책이 충돌하지 않는가?</li>
</ol>
<p>A2A v1.2는 이 문제를 <strong>Signed Agent Cards</strong>로 해결한다:</p>
<pre><code class="language-typescript">// A2A Agent Card 구조 (v1.2)
interface AgentCard {
  name: string;                    // "Vertex AI Code Agent"
  version: "1.2";
  endpoint: string;                // "https://agent.vertex.ai/a2a/a1b2c3"

  // Cryptographic identity (v1.2 new)
  capabilities: string[];          // ["code_generation", "git_ops", "data_analysis"]
  skills: Skill[];

  // NEW in v1.2: Signed identity
  identity: {
    provider: "google-cloud";
    agentId: string;               // "projects/.../agents/..." (full resource path)
    domain: string;                // "vertex.ai"
    signingKey: {
      // JWK format — ECDSA P-256 signing key
      kty: "EC",
      crv: "P-256",
      x: "base64url...",           // Agent-specific signing key
      y: "base64url...",
      kid: "a1b2c3-key-001"
    };
    certificateChain: string[];    // Intermediate + root CA certs
  };

  security: {
    requiredAuthScopes: string[];  // ["https://.googleapis.com/auth/bigquery"]
    allowedDomains: string[];     // ["salesforce.com", "service-now.com"]
    dataClassification: "confidential" | "internal" | "public";
  };
}
</code></pre>
<p><strong>서명 검증 프로세스</strong>:</p>
<pre><code class="language-python"># a2a/agent_card_verifier.py
import json
import base64
import hashlib
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.asymmetric import ec
from cryptography.x509 import load_pem_x509_certificate
from cryptography.exceptions import InvalidSignature

class AgentCardVerifier:
    def __init__(self, root_certs: dict[str, str]):
        self.root_certs = root_certs  # provider -> root CA cert

    def verify(self, agent_card: AgentCard) -> bool:
        """A2A v1.2 signed agent card verification"""

        # 1. Verify signing key is signed by known provider CA
        if not self._verify_key_chain(agent_card.identity):
            raise TrustError("Key chain verification failed")

        # 2. Verify agent card content integrity
        card_bytes = json.dumps(agent_card, sort_keys=True).encode()
        expected_hash = hashlib.sha256(card_bytes).digest()

        signature = base64url_decode(agent_card._signature)

        try:
            public_key = self._reconstruct_public_key(agent_card.identity.signingKey)
            public_key.verify(signature, expected_hash, ec.ECDSA(hashes.SHA256()))
        except InvalidSignature:
            raise TrustError("Agent card signature mismatch")

        # 3. Verify domain matches provider
        if not self._verify_domain(agent_card.identity):
            raise TrustError("Domain verification failed")

        return True

    def _verify_key_chain(self, identity: Identity) -> bool:
        """Verify signing key is authorized by known provider"""
        # Recursively verify certificate chain up to root CA
        cert = load_pem_x509_certificate(identity.certificateChain[0])
        issuer = identity.certificateChain[1] if len(identity.certificateChain) > 1 else None

        if issuer and issuer in self.root_certs:
            # Verify cert is signed by root
            root_cert = load_pem_x509_certificate(self.root_certs[issuer])
            cert.verify_extension_for_issuer(root_cert.public_key())
            return True
        elif self._is_self_signed(identity):
            return identity.domain in self.root_certs  # root CA for known domains

        return False
</code></pre>

from sklearn.preprocessing import StandardScaler

axes[0].set_xlabel('K'); axes[1].set_xlabel('Rating')

<h2 id="section-9-결론-pieces-not-platform-이-진짜-문제였다는-증명" tabindex="-1">9. 결론: "Pieces not Platform"이 진짜 문제였다는 증명<a href="#section-9-%EA%B2%B0%EB%A1%A0-pieces-not-platform-%EC%9D%B4-%EC%A7%84%EC%A7%9C-%EB%AC%B8%EC%A0%9C%EC%98%80%EB%8B%A4%EB%8A%94-%EC%A6%9D%EB%AA%85" class="heading-anchor" aria-label="9. 결론: &#x22;Pieces not Platform&#x22;이 진짜 문제였다는 증명 항목 링크">#</a></h2>
<p>Google Cloud Next 2026의 핵심 메시지는 기술적이다기보다 전략적이다:</p>
