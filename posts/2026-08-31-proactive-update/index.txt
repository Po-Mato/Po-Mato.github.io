1a:T29ab,<h1>AI 에이전트의 작업 분해와 컨텍스트 관리</h1>
<p>작업을 여러 단계로 나누는 것만으로 실행이 안전해지지는 않습니다. 앞 단계가 실패했을 때 어떤 작업을 멈추고 어떤 작업을 계속할지 명시해야 합니다. 이 글은 <strong>이미 정해진 작업 그래프를 순차 실행하는 로컬 실습</strong>입니다. 모델 추론이나 자동 작업 분해, 실제 배포를 구현하지 않습니다.</p>
<h2 id="section-1-ai-어시스턴트에서-agentic-ai로" tabindex="-1">1. AI 어시스턴트에서 Agentic AI로<a href="#section-1-ai-%EC%96%B4%EC%8B%9C%EC%8A%A4%ED%84%B4%ED%8A%B8%EC%97%90%EC%84%9C-agentic-ai%EB%A1%9C" class="heading-anchor" aria-label="1. AI 어시스턴트에서 Agentic AI로 항목 링크">#</a></h2>
<p>코드 생성 도구에 여러 작업을 맡길 때도 실행 상태를 검토할 수 있어야 합니다. 여기서는 작업마다 선행 작업과 실행 함수를 선언합니다. 모든 선행 작업이 성공해야 다음 작업을 실행하고, 실패와 건너뜀을 구분합니다. 서로 독립적인 작업은 계속합니다.</p>
<h2 id="section-2-기술적-깊이-agentic-ai의-작동-원리" tabindex="-1">2. 기술적 깊이: Agentic AI의 작동 원리<a href="#section-2-%EA%B8%B0%EC%88%A0%EC%A0%81-%EA%B9%8A%EC%9D%B4-agentic-ai%EC%9D%98-%EC%9E%91%EB%8F%99-%EC%9B%90%EB%A6%AC" class="heading-anchor" aria-label="2. 기술적 깊이: Agentic AI의 작동 원리 항목 링크">#</a></h2>
<p>이 실습은 추론 대신 실행 계약에 집중합니다. <code>build → test → package → publish</code>에서 test가 실패하면 package와 publish는 실행하지 않습니다. 독립적인 docs는 성공할 수 있습니다. 결과의 blocked_by는 바로 앞의 차단 원인을 가리키므로 publish의 원인은 package입니다.</p>
<h3 id="section-코드-예시-간단한-task-orchestration-python" tabindex="-1">코드 예시: 간단한 Task Orchestration (Python)<a href="#section-%EC%BD%94%EB%93%9C-%EC%98%88%EC%8B%9C-%EA%B0%84%EB%8B%A8%ED%95%9C-task-orchestration-python" class="heading-anchor" aria-label="코드 예시: 간단한 Task Orchestration (Python) 항목 링크">#</a></h3>
<p>입력 ID는 비어 있지 않고 고유해야 하며 실행 함수는 호출 가능해야 합니다. 없는 선행 작업과 순환은 어떤 함수도 실행하기 전에 거절합니다. 실행 함수가 예외 없이 반환하면 성공으로 정의합니다. 반환값 False도 자동으로 실패가 되지 않으므로 실패를 알릴 때는 예외를 발생시켜야 합니다.</p>
<h3 id="section-로컬-실습-실패와-건너뜀-구분하기" tabindex="-1">로컬 실습: 실패와 건너뜀 구분하기<a href="#section-%EB%A1%9C%EC%BB%AC-%EC%8B%A4%EC%8A%B5-%EC%8B%A4%ED%8C%A8%EC%99%80-%EA%B1%B4%EB%84%88%EB%9C%80-%EA%B5%AC%EB%B6%84%ED%95%98%EA%B8%B0" class="heading-anchor" aria-label="로컬 실습: 실패와 건너뜀 구분하기 항목 링크">#</a></h3>
<p>Python 3.10 이상과 표준 라이브러리만 사용합니다. <a href="/examples/task-lab.py">task-lab.py 내려받기</a>. 아래 전체 코드와 다운로드 파일은 같습니다.</p>
<pre><code class="language-python">"""Python 3.10+ 표준 라이브러리 작업 상태 실습: 외부 요청 없음."""
from dataclasses import dataclass
from graphlib import TopologicalSorter
from typing import Callable
import unittest


@dataclass(frozen=True)
class Task:
    id: str
    needs: tuple[str, ...]
    run: Callable[[], object]


def run_tasks(tasks: list[Task]) -> dict:
    by_id = {}
    for task in tasks:
        if not isinstance(task.id, str) or not task.id.strip():
            raise ValueError("빈 작업 ID")
        if task.id in by_id:
            raise ValueError("중복 작업 ID")
        if not callable(task.run):
            raise ValueError("호출 불가능한 작업")
        by_id[task.id] = task
    for task in tasks:
        if any(dep not in by_id for dep in task.needs):
            raise ValueError("없는 선행 작업")
    # 전체 순서를 먼저 확정한다. 순환이 있으면 실행 전에 CycleError.
    order = tuple(TopologicalSorter({t.id: t.needs for t in tasks}).static_order())
    results = {}
    for task_id in order:
        task = by_id[task_id]
        blocked = [dep for dep in task.needs if results[dep]["state"] != "success"]
        if blocked:
            results[task_id] = {"state": "skipped", "blocked_by": blocked}
            continue
        try:
            value = task.run()
        except Exception as error:
            results[task_id] = {"state": "failed", "error": str(error)}
        else:
            results[task_id] = {"state": "success", "value": value}
    return results


class TaskTests(unittest.TestCase):
    def setUp(self):
        self.calls = []

    def task(self, name, needs=(), fail=False):
        def action():
            self.calls.append(name)
            if fail:
                raise RuntimeError("검증 실패")
            return name + " 완료"
        return Task(name, needs, action)

    def test_success_and_once(self):
        tasks = [self.task("build"), self.task("test", ("build",)),
                 self.task("package", ("build", "test"))]
        result = run_tasks(tasks)
        self.assertEqual([r["state"] for r in result.values()], ["success"] * 3)
        self.assertEqual(result["package"]["value"], "package 완료")
        self.assertEqual(self.calls, ["build", "test", "package"])

    def test_failure_propagation_and_independent_work(self):
        tasks = [self.task("build"), self.task("test", ("build",), fail=True),
                 self.task("package", ("build", "test")),
                 self.task("publish", ("package",)), self.task("docs")]
        result = run_tasks(tasks)
        self.assertEqual(result["test"], {"state": "failed", "error": "검증 실패"})
        self.assertEqual(result["package"], {"state": "skipped", "blocked_by": ["test"]})
        self.assertEqual(result["publish"], {"state": "skipped", "blocked_by": ["package"]})
        self.assertEqual(result["docs"]["state"], "success")
        self.assertCountEqual(self.calls, ["build", "test", "docs"])

    def test_invalid_graph_runs_nothing(self):
        cases = [
            [self.task("a"), self.task("a")],
            [self.task("a", ("missing",))],
            [self.task("a", ("a",))],
            [self.task("a", ("b",)), self.task("b", ("a",))],
            [self.task(" ")], [Task("a", (), None)],
        ]
        for tasks in cases:
            with self.subTest(tasks=tasks):
                with self.assertRaises(ValueError):
                    run_tasks([self.task("independent")] + tasks)
                self.assertEqual(self.calls, [])

    def test_empty(self):
        self.assertEqual(run_tasks([]), {})

    def test_process_signals_propagate(self):
        for exception in (KeyboardInterrupt, SystemExit):
            def stop():
                raise exception()
            with self.assertRaises(exception):
                run_tasks([Task("stop", (), stop)])

<h2 id="section-3-엔지니어가-준비해야-할-것" tabindex="-1">3. 엔지니어가 준비해야 할 것<a href="#section-3-%EC%97%94%EC%A7%80%EB%8B%88%EC%96%B4%EA%B0%80-%EC%A4%80%EB%B9%84%ED%95%B4%EC%95%BC-%ED%95%A0-%EA%B2%83" class="heading-anchor" aria-label="3. 엔지니어가 준비해야 할 것 항목 링크">#</a></h2>
<p>위상 정렬은 실행 순서만 정합니다. 작업 성공을 보장하지 않습니다. Python의 TopologicalSorter는 정의하지 않은 선행 노드를 자동 추가하기 때문에 이 실습은 누락 검사를 별도로 수행합니다. 순환 검사는 전체 실행 전에 끝냅니다.</p>
<p>각 함수는 한 실행에서 최대 한 번 호출하지만 프로그램을 다시 실행하면 다시 호출됩니다. 영속 저장·중복 요청 방지·트랜잭션·롤백은 제공하지 않습니다. 실패 전 발생한 부작용을 되돌리지도 않습니다. 함수가 멈추지 않으면 전체 실행도 기다리므로 실제 서비스에는 별도의 시간 제한과 격리가 필요합니다. 재시도·병렬 처리·외부 모델 호출은 범위 밖입니다. KeyboardInterrupt와 SystemExit는 작업 실패로 삼키지 않고 호출자에게 전달합니다.</p>
