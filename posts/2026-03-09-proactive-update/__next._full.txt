15:T16fd,<h1>Next.js 프로젝트의 기술 부채 청산 전략: Lint부터 Vitest까지</h1>
<p>프로젝트가 성숙해짐에 따라 필연적으로 발생하는 **기술 부채(Technical Debt)**는 적시에 해결하지 않으면 개발 속도를 저하시키고 안정성을 해치는 암초가 됩니다. 최근 본 블로그 프로젝트(<code>Po-Mato/tech-blog</code>)에서 진행한 대규모 부채 상환 과정을 바탕으로, 어떻게 시스템적으로 품질을 강제할 수 있는지 아키텍처 관점에서 분석합니다.</p>
<h2 id="section-1-기술-부채의-식별과-우선순위" tabindex="-1">1. 기술 부채의 식별과 우선순위<a href="#section-1-%EA%B8%B0%EC%88%A0-%EB%B6%80%EC%B1%84%EC%9D%98-%EC%8B%9D%EB%B3%84%EA%B3%BC-%EC%9A%B0%EC%84%A0%EC%88%9C%EC%9C%84" class="heading-anchor" aria-label="1. 기술 부채의 식별과 우선순위 항목 링크">#</a></h2>
<p>이번 부채 청산 작업에서는 다음과 같은 문제들을 우선순위별로 해결했습니다.</p>
<ol>
<li><strong>품질 게이트의 부재</strong>: Lint 에러가 있음에도 빌드와 배포가 성공하는 구조.</li>
<li><strong>런타임 예측 불가능성</strong>: Effect 내에서의 동기 <code>setState</code> 및 불순한 <code>Date.now()</code> 사용.</li>
<li><strong>테스트 자동화 결핍</strong>: 핵심 로직 변경 시 수동 검증에 의존.</li>
</ol>
<h2 id="section-2-아키텍처-개선-품질-게이트-도입" tabindex="-1">2. 아키텍처 개선: 품질 게이트 도입<a href="#section-2-%EC%95%84%ED%82%A4%ED%85%8D%EC%B2%98-%EA%B0%9C%EC%84%A0-%ED%92%88%EC%A7%88-%EA%B2%8C%EC%9D%B4%ED%8A%B8-%EB%8F%84%EC%9E%85" class="heading-anchor" aria-label="2. 아키텍처 개선: 품질 게이트 도입 항목 링크">#</a></h2>
<p>기존의 CI 파이프라인이 단순히 "빌드 가능 여부"만 체크했다면, 개선된 아키텍처는 <strong>3단계 검증 게이트</strong>를 거칩니다.</p>
<h3 id="section-품질-검증-파이프라인-아키텍처" tabindex="-1">품질 검증 파이프라인 아키텍처<a href="#section-%ED%92%88%EC%A7%88-%EA%B2%80%EC%A6%9D-%ED%8C%8C%EC%9D%B4%ED%94%84%EB%9D%BC%EC%9D%B8-%EC%95%84%ED%82%A4%ED%85%8D%EC%B2%98" class="heading-anchor" aria-label="품질 검증 파이프라인 아키텍처 항목 링크">#</a></h3>
<ol>
<li><strong>Static Analysis (Lint)</strong>: 코드 스타일 및 잠재적 버그 사전 차단.</li>
<li><strong>Unit Tests (Vitest)</strong>: 비즈니스 로직의 회귀 방지.</li>
<li><strong>Build Verification</strong>: 최종 번들링 및 배포 가능성 확인.</li>
</ol>
<h2 id="section-3-실전-코드-예시" tabindex="-1">3. 실전 코드 예시<a href="#section-3-%EC%8B%A4%EC%A0%84-%EC%BD%94%EB%93%9C-%EC%98%88%EC%8B%9C" class="heading-anchor" aria-label="3. 실전 코드 예시 항목 링크">#</a></h2>
<h3 id="section-3-1-린트-에러-해결-react-purity-확보" tabindex="-1">3.1 린트 에러 해결 (React Purity 확보)<a href="#section-3-1-%EB%A6%B0%ED%8A%B8-%EC%97%90%EB%9F%AC-%ED%95%B4%EA%B2%B0-react-purity-%ED%99%95%EB%B3%B4" class="heading-anchor" aria-label="3.1 린트 에러 해결 (React Purity 확보) 항목 링크">#</a></h3>
<p><code>setState</code>를 Effect 내부에서 동기적으로 호출하던 패턴을 클릭 핸들러 내부로 이동시켜 불필요한 렌더링을 방지했습니다.</p>
<pre><code class="language-tsx">// 개선 전

// 개선 후
const handleStart = () => {
  setIsPlaying(true);
