<p>도구를 반복 실행하는 에이전트를 설계할 때는 실패 후 언제 다시 시도하고 언제 멈출지 정해야 합니다. 이 글에서는 구성 요소를 구분한 뒤, 외부 모델 없이 단일 작업의 종료 경계를 직접 검증합니다.</p>
<h2 id="section-agentic-ai의-아키텍처적-핵심" tabindex="-1">Agentic AI의 아키텍처적 핵심<a href="#section-agentic-ai%EC%9D%98-%EC%95%84%ED%82%A4%ED%85%8D%EC%B2%98%EC%A0%81-%ED%95%B5%EC%8B%AC" class="heading-anchor" aria-label="Agentic AI의 아키텍처적 핵심 항목 링크">#</a></h2>
<ul>
<li><strong>추론</strong>: 다음 작업이나 계획을 제안합니다. 제안이 안전하거나 실행 가능하다는 보장은 별도로 검증해야 합니다.</li>
<li><strong>도구</strong>: 파일 읽기나 API 호출처럼 실제 효과를 만드는 인터페이스입니다. 권한과 실패 분류는 실행 계층에서 관리합니다.</li>
<li><strong>메모리</strong>: 이전 입력과 결과를 보관해 후속 판단에 제공합니다. 기록을 저장하는 것 자체가 모델 학습이나 품질 향상을 뜻하지는 않습니다.</li>
</ul>
<h3 id="section-간단한-워크플로우-예시-conceptual" tabindex="-1">간단한 워크플로우 예시 (Conceptual)<a href="#section-%EA%B0%84%EB%8B%A8%ED%95%9C-%EC%9B%8C%ED%81%AC%ED%94%8C%EB%A1%9C%EC%9A%B0-%EC%98%88%EC%8B%9C-conceptual" class="heading-anchor" aria-label="간단한 워크플로우 예시 (Conceptual) 항목 링크">#</a></h3>
<p>흐름은 계획 제안 → 허용된 도구 실행 → 결과 검사 → 종료 또는 다음 시도입니다. 기존 예제처럼 실패할 때 execute_task를 재귀 호출하면 지속 실패 시 재귀 한도에 도달하고, 돌아온 뒤 이전 계획을 계속 실행할 수도 있습니다. 재계획과 재시도를 구분하고 종료 결과를 호출자에게 반환해야 합니다.</p>
<h3 id="section-로컬-실습-재시도-예산과-취소" tabindex="-1">로컬 실습: 재시도 예산과 취소<a href="#section-%EB%A1%9C%EC%BB%AC-%EC%8B%A4%EC%8A%B5-%EC%9E%AC%EC%8B%9C%EB%8F%84-%EC%98%88%EC%82%B0%EA%B3%BC-%EC%B7%A8%EC%86%8C" class="heading-anchor" aria-label="로컬 실습: 재시도 예산과 취소 항목 링크">#</a></h3>

<p>max_attempts는 최초 호출을 포함합니다. 1 이상의 정수만 허용하며 bool은 거절합니다. 각 호출 직전에 취소를 검사하므로 실행 중인 동기 함수를 강제로 중단하지는 못합니다. 마지막 허용 시도라도 성공은 성공으로 반환하고, 이미 완료한 성공을 사후 취소로 바꾸지 않습니다.</p>
<pre><code class="language-python">"""네트워크나 대기 없이 단일 작업의 재시도 경계를 검증합니다."""
from dataclasses import dataclass
import unittest


class RetryableError(Exception):
    pass


class PermanentError(Exception):
    pass


@dataclass(frozen=True)
class Result:
    reason: str
    attempts: int
    value: object = None
    error: str | None = None


def run_retry(task, max_attempts, cancelled=lambda: False):
    if type(max_attempts) is not int or max_attempts &#x3C; 1:
        raise ValueError("max_attempts는 1 이상의 정수여야 합니다")
    attempts = 0
    last_error = None
    for _ in range(max_attempts):
        if cancelled():
            return Result("cancelled", attempts, error=last_error)
        attempts += 1
        try:
            value = task()
        except RetryableError as error:
            last_error = str(error)
        except PermanentError as error:
            return Result("permanent_error", attempts, error=str(error))
        else:
            return Result("success", attempts, value=value)
    return Result("exhausted", attempts, error=last_error)


class RetryTests(unittest.TestCase):
    def fixture(self, outcomes):
        calls = []

        def task():
            index = len(calls)
            calls.append(index)
            outcome = outcomes[min(index, len(outcomes) - 1)]
            if isinstance(outcome, BaseException):
                raise outcome
            return outcome

        return task, calls

    def test_success(self):
        for outcomes, budget in [(["완료"], 3),
                                 ([RetryableError("대기"), "완료"], 3),
                                 ([RetryableError("대기"), "완료"], 2)]:
            with self.subTest(outcomes=outcomes, budget=budget):
                task, calls = self.fixture(outcomes)
                self.assertEqual(run_retry(task, budget),
                                 Result("success", len(outcomes), "완료"))
                self.assertEqual(len(calls), len(outcomes))

    def test_permanent_error(self):
        task, calls = self.fixture([PermanentError("권한 없음"), "실행 금지"])
        self.assertEqual(run_retry(task, 3),
                         Result("permanent_error", 1, error="권한 없음"))
        self.assertEqual(len(calls), 1)

    def test_exhausted(self):
        task, calls = self.fixture([RetryableError("첫 오류"), RetryableError("마지막 오류")])
        self.assertEqual(run_retry(task, 2),
                         Result("exhausted", 2, error="마지막 오류"))
        self.assertEqual(len(calls), 2)

    def test_invalid_budget(self):
        for budget in [0, -1, True, False, 1.5, "2", None]:
            with self.subTest(budget=budget):
                task, calls = self.fixture(["실행 금지"])
                with self.assertRaises(ValueError):
                    run_retry(task, budget)
                self.assertEqual(calls, [])

    def test_cancel_before_start(self):
        task, calls = self.fixture(["실행 금지"])
        self.assertEqual(run_retry(task, 2, lambda: True), Result("cancelled", 0))
        self.assertEqual(calls, [])

    def test_cancel_between_attempts(self):
        task, calls = self.fixture([RetryableError("중단 요청"), "실행 금지"])
        self.assertEqual(run_retry(task, 3, lambda: bool(calls)),
                         Result("cancelled", 1, error="중단 요청"))
        self.assertEqual(len(calls), 1)

    def test_completed_success_wins(self):
        task, calls = self.fixture(["완료"])
        self.assertEqual(run_retry(task, 2, lambda: bool(calls)),
                         Result("success", 1, "완료"))
        self.assertEqual(len(calls), 1)

    def test_unexpected_errors_propagate(self):
        for error in [RuntimeError("버그"), KeyboardInterrupt(), SystemExit(2)]:
            with self.subTest(error=type(error).__name__):
                task, calls = self.fixture([error])
                with self.assertRaises(type(error)):
                    run_retry(task, 3)
                self.assertEqual(len(calls), 1)

<p>이 예제는 RetryableError만 재시도하고 PermanentError는 종료 결과로 반환합니다. 예상하지 않은 오류와 KeyboardInterrupt/SystemExit는 호출자에게 전파합니다. 실서비스의 어떤 오류가 일시적인지는 API 계약과 작업 성격을 근거로 분류해야 합니다.</p>
<p>재시도는 중복 부작용을 만들 수 있습니다. 결제·배포처럼 효과가 있는 작업에는 멱등성 키나 중복 방지, 재시도 간 백오프, 호출별 시간 제한과 전체 마감 시간을 별도로 설계해야 합니다. 이 실행기는 그런 기능이나 실행 중 강제 취소를 제공하지 않습니다. 여러 작업의 의존성과 실패 전파는 <a href="/posts/2026-08-31-proactive-update/">작업 그래프 실습</a>에서 따로 다룹니다.</p>
<p>구현 근거는 Python 공식 <a href="https://docs.python.org/3/tutorial/errors.html">예외 처리</a>와 <a href="https://docs.python.org/3/library/unittest.html">unittest</a>입니다. 지정한 예외만 처리하고 다른 예외를 전파하는 동작, assertEqual/assertRaises 기반 검사를 사용했습니다.</p>
